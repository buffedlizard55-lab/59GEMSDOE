Executive summary — how to make a submission

The one-paragraph version

The current candidate is gems59-h59j-offcat-propen-30k-20261011.tif: a 30,000-dot binary GeoTIFF on the official grid, on the correct CRS/shape/transform, with all values in [0, 1], no NaN, and zero dots on the mapped catalogue (those pixels are masked by the scorer). It is byte-unique against all 695 pinned registry rasters. It is safe to download, but it is not cleared for a weekly slot: the lane's proxy instrument ranks live scores only inside the catalogue-adjacent family, and the propagation conditions are written down in the promotion decision. Promotion is the owner's selector step — nothing on this site has been uploaded, and no submission slot has been spent.

2. Check the status banner before you upload

The status page carries an explicit two-part verdict at the top: DOWNLOAD: OK SUBMIT: NO. The verdict is generated from the receipts, not from prose: download_status and submit_status live in docs/data/submission_h59j.json, and promotion_decision.what_would_clear_it states exactly what would change the second badge. The machine-readable index of every file is downloads/manifest.json. If the banner says SUBMIT: NO, do not upload (the file will not be rejected — it is format-valid — but the selector has not cleared it).

3. Submit on DrivenData (only after the owner promotes the file)

  1. Open the competition submission page (problem/metric: page 967).
  2. File to submit: choose the downloaded .tif (or the .zip containing exactly one GeoTIFF). The portal requires a single-band GeoTIFF matching the sample submission's CRS, shape and geotransform.
  3. Note (optional, ≤ 140 characters; the text below is 122): paste H59-J off-catalogue discriminant, 30k dots, 3px spacing, 0 on catalogue; proxy 0.375 vs incumb 0.295; organiser-unverified
  4. Click Create submission. The weekly cap is shown on the logged-in page; this project has used none of it.

The earlier portal error “Predicted values must be in range [0, 1]” is produced by non-finite or out-of-range cells inside the scored footprint (a common cause is an unmasked -3.4028e38 sentinel). The shared fail-closed writer refuses to clip or repair values, and both candidates here carry zero NaNs, zero infinities and only 0.0/1.0 values — so that error cannot originate from these bytes (still: verify the SHA256 after download; a truncated upload would be a different file).
